# 采购分析技能（操作手册）

## 适用场景
- 供应商比价分析（多供应商、同物料价格对比）
- 物料行情评估（价格趋势、供需分析）
- 供应商综合评分（按信用评级、价格、交期加权打分）
- 采购策略建议（分阶段采购、集中采购、备选供应商推荐）
- 生成含图表的采购分析报告

## 分析流程（5 步）

### 第 1 步：理解需求
- 从任务描述中提取：【任务目标】、【用户偏好】、【分析需求正文】
- 明确分析维度：供应商对比？价格趋势？物料筛选？综合评估？

### 第 2 步：收集数据

**简单检索快速路径（优先级高于完整分析流程）**
- 如果需求只是“查询/查找名称包含某关键词的供应商、物料或订单”，只调用对应 ERP 查询工具一次并直接返回结果，不进入外部核验、Python 分析、图表和报告步骤。
- 工具调用成功但返回空列表，直接判定为“当前查询条件无匹配记录”。不得拆词、猜词、逐字枚举、用其他关键词对照、扫描全库或重复查询来证明空结果。
- 只有工具明确报错时才按完全相同的参数重试一次；正常空结果不重试。

**2a. ERP 内部数据（必须）**
- `supplier_query(name="供应商名")` → 供应商列表
- `part_query(name="物料名")` 或 `part_search(name="物料名")` → 零部件
- `part_by_supplier(supplier_id=N)` → 按供应商查零部件
- `order_search_details(part_name="xxx")` → 历史订单价格
- `inventory_warning()` → 库存预警
- 收集时记录查询条件、业务日期、获取时间、记录数及分页是否完整；按供应商、物料和订单明细的唯一标识去重，避免重复统计。

**2b. 外部数据（必须尝试核验）**
1. 激活 `/skills/procurement/supplier-price-urls/`，读取 `data/url_mapping.yaml`
2. 按零部件名 + 供应商名查找对应报价 URL
3. **找到 URL** → 使用 `web-scraper` 直接抓取：
   ```bash
   execute("python /skills/procurement/web-scraper/scrape_page.py --url '<报价URL>'")
   ```
   脚本将 HTML 转为 Markdown 保存到 `/analysis/temp/{filename}.md`，再 `read_file` 读取内容提取价格/型号/品牌/材质/单位。
4. **未找到 URL** → 使用 `web_search` 搜索市场价格和规格参数
5. 保存原文链接、发布/报价日期、抓取时间及价格适用条件；搜索摘要只作线索，未核验原文时标注“未核验”。
6. 若无法获取有效外部数据，记录已尝试的渠道和限制，在报告中说明“缺少外部价格验证”；可以完成内部分析，不编造市场价格，也不据此断言“低于市场价”。

### 第 3 步：执行分析
1. 编写 Python 分析脚本，使用 `execute` 工具运行
2. 如需安装依赖：`pip install -i https://mirrors.aliyun.com/pypi/simple/ pandas matplotlib numpy`（已自动路由到 `/opt/skills-venv/bin/pip`）
3. 常见分析维度：
   - 价格对比：同规格、同单位、同币种及税费口径下的最低价、最高价、价差；历史均价注明计算方法
   - 供应商评估：先检查规格、起订量、交期等硬约束，再比较价格、信用评级等已知信息；需要评分时披露权重和评分规则
   - 物料质量：规格参数对比
   - 综合排名：多维度加权评分
4. 中间结果保留在上下文（`execute` 工具输出）；关键计算口径、输入来源和结果写入最终报告，便于复核。

### 第 4 步：生成图表
1. 常见类型按 `generate_chart` 描述中的紧凑格式调用；高级选项、地图或不确定字段时，读取 `/skills/analyis_chart_params.md` 对应分组。
2. 遵循用户的表格/图表偏好；通常选择 0-3 张能支持结论的图表，简单对比用表格即可，不为凑数量绘图。
3. 调用 `generate_chart(chart_type="xxx", chart_config={...})`。只有 `width/height` 通用；标题、主题、样式和坐标轴字段须按图表类型选择。
4. 图表与对应分析放在一起，注明单位、时间范围、来源及一句话解读；图表数据必须与正文、表格一致。
5. 参考文件只读一次；参数报错时对照参考文件修正后重试。生成失败则保留数据表并说明，不能编造图片链接。

### 第 5 步：生成报告
1. 按下方模板组织报告；保留与任务相关的章节，先回答采购决策，再展开数据和依据。
2. 写入 `/analysis/report_{timestamp}.md`，其中时间戳使用实际生成时间，如 `YYYYMMDD_HHMMSS`。
3. 写入后用 `read_file` 检查关键金额、来源引用、图表链接及未替换的占位符，再返回报告路径和摘要。

### 指标与表达口径

- **历史采购加权均价**：`Σ(明细单价 × 明细数量) / Σ明细数量`，只使用相同物料、单位及币种口径的有效明细，合计数量须大于 0；说明取消订单、退货和异常记录如何处理。若用简单均价，明确标注“简单均价”及样本是报价还是历史成交明细。
- **相对基准价差率**：`(比较单价 - 基准单价) / 基准单价 × 100%`，正值表示更贵、负值表示更便宜；基准为 0 或缺失时不计算。
- **预计节省**：`基准方案总成本 - 推荐方案总成本`；节省率以基准方案总成本为分母，仅在基准总成本大于 0 时计算。两方案应采用相同需求数量、规格和费用范围；不能只用价差代替总成本差额。
- **成本范围**：采购金额可按 `Σ(数量 × 单价)` 计算，已知运费、税费、固定费用按实际规则计入且不重复计费。费用不完整时写“已知成本/仅货款”，不得把未知费用当作 0，也不宣称已经实现节省。
- **交付与库存**：预计交期不等于实际交付表现；没有实际交付记录不计算准时交付率，没有库存量和消耗速率不计算可用天数。`inventory_warning()` 的结果仅代表该接口返回的预警范围。
- **数值展示**：币种、计量单位和期间随指标列明；单价保留业务所需精度，总额通常保留两位小数，百分比通常保留一位。计算保留完整精度，多币种未统一换算时分别展示、不直接汇总。

### 交付前核对

- 结论能否追溯到来源；事实、推断与假设是否区分；推荐是否满足已知硬约束。
- 数量、单价、小计和总计是否对应；价差分母、评分权重、分单比例是否一致；缺失费用是否已披露。
- 图表是否使用真实返回的 URL，且与正文采用同一批数据；无图时是否有足够的表格或文字依据。
- 是否删除未替换的 `{{…}}`、写作说明和无关章节；缺口是否转化为明确的下一步。

- DeepAgents 已内置自动 offload（>20k tokens）和 Summarization（85% 上下文阈值）
- 你只需显式写入：`/analysis/report_*.md`
- 其余工具返回由框架自动管理

## 关键原则
- **技能发现**：每次任务开始先 `ls /skills/procurement/` 扫描可用技能，不依赖静态列表
- **数据真实**：所有结论基于真实数据，不编造
- **先决策后依据**：完整报告按任务需要展开；返回主 Agent 的摘要通常不超过 500 字，结论通常 3-5 条。
- **可比与可追溯**：先对齐报价条件再比较；缺数据时缩小结论范围，不补造数字或来源。
- **成本意识**：先获取必要数据，避免无限循环查询
